# Commit 5931c52 - Fix Pre-commit Hook Running on All Bash Commands

## Problem

The pre-commit hook was running for every bash command and raising errors when it wasn't a git command.

## Root Cause

Two issues were identified:

1. **Prompt hook always produces output**: The settings.json had a prompt hook that ran for all Bash commands. Prompt hooks cannot silently skip - they always produce output, causing confusing error messages for non-git commands.

2. **Bash script error handling**: The pre-commit.sh script didn't handle cases where `jq` might fail (not installed, invalid JSON input).

## Solution

1. Removed the redundant prompt hook from `.claude/settings.json` - the bash script already handles pre-commit validation (format, lint, typecheck, tests)

2. Made the bash script more robust in `.claude/hooks/pre-commit.sh`:
   - Added `2>/dev/null` to suppress jq errors
   - Added `|| exit 0` to silently exit if jq fails
   - Added check for empty `$COMMAND` to handle edge cases
